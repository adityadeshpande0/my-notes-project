## Intuition

An <Term id="array">array</Term> is a row of numbered lockers in a hallway. If you know the
locker number, you walk straight to it. You don't open the lockers before it.

That's why reading `arr[i]` is fast however long the hallway is. The locker number is
called the <Term id="index">index</Term>, and it starts at 0.

## How it works

1. The array's items are stored <Term id="contiguous">next to each other</Term> in memory.
2. To find item `i`, the computer does one sum: `start + i × itemSize`.
3. One sum, whatever the size of the array. That's called <Term id="constant-time">constant
   time</Term>, written `O(1)`.

Inserting at the **front** is a different story. Every item has to shift one place to the right
to make room. With `n` items that's `n` moves, which is <Term id="linear-time">linear time</Term>,
written `O(n)`.

### So what is Big-O?

In short, <Term id="big-o">Big-O</Term> describes _how the work grows as the input grows_.
It isn't a stopwatch. It tells you the shape of the curve:

- `O(1)`: flat. 10 items or 10 million, same work.
- `O(log n)`: grows very slowly. Doubling the input adds one step.
- `O(n)`: a straight line. Double the input, double the work.
- `O(n²)`: grows fast. Double the input, four times the work.

## Code

```ts
const scores = [42, 17, 99, 8];

// O(1): jump straight to index 2
const third = scores[2]; // 99

// O(n): look at every item until we find it
function indexOf(arr: number[], target: number): number {
  for (let i = 0; i < arr.length; i++) {
    if (arr[i] === target) return i;
  }
  return -1;
}
```

## Complexity

| Operation           | Time   | Why                                                                       |
| ------------------- | ------ | ------------------------------------------------------------------------- |
| Read `arr[i]`       | `O(1)` | One address calculation                                                   |
| Push to the end     | `O(1)` | Usually there's spare room. <Term id="amortized">On average</Term>, cheap |
| Insert at the front | `O(n)` | Every item shifts right                                                   |
| Search (unsorted)   | `O(n)` | Might have to check every item                                            |

## Common mistakes

- **<Term id="off-by-one">Off-by-one errors.</Term>** The last index is `arr.length - 1`, not
  `arr.length`.
- **Thinking Big-O means seconds.** It describes how cost _grows_ with input size, not how long
  something takes on your laptop.
- **Inserting at the front in a loop.** Each insert is `O(n)`, so `n` of them is `O(n²)`. Build
  the array backwards, or push and reverse once at the end.

<Callout kind="tip">
  Big-O drops constants: `O(2n)` is just `O(n)`. We care about the shape of the growth, not the
  exact count.
</Callout>
